# Bandit Levels 00 to 07 Walkthrough & Core Concepts

---

## Level 0 to Level 1: Remote Access & Encrypted Channels

Objective: Establish an authenticated, encrypted interactive shell session with the remote game server host.

Commands:
ssh bandit0@bandit.labs.overthewire.org -p 2220
ls
cat readme
exit

Core Concepts Learned:
1. Transport Layer Port Addressing (-p 2220): Standard SSH daemons listen on TCP port 22. Labs and servers often remap SSH to alternative ports like 2220 to avoid scanner noise or conflicts. The -p flag forces OpenSSH to target port 2220.
2. Host Authentication & Fingerprint Verification: On initial connection, SSH warns that the authenticity cannot be established and checks the remote public key against ~/.ssh/known_hosts to protect against Man-in-the-Middle (MitM) attacks.
3. Standard File Output (cat): The cat utility reads files sequentially and streams their contents to standard output (stdout).

## Level 1 to Level 2: Dashed Filenames & Argument Parsing

Objective: Read the contents of a file named "-" in the home directory.

Commands:
cat ./-
cat -- -

Core Concepts Learned:
1. POSIX Option Parsing: CLI utilities treat tokens starting with "-" as options/flags rather than file arguments.
2. Special Meaning of Single Dash (-): In tools like cat, a lone "-" represents stdin (standard input), causing the shell to wait for keyboard input rather than opening a file.
3. Path Disambiguation (./-): Adding the relative path prefix "./" prevents the parser from reading "-" as a flag because the argument starts with ".".
4. End-of-Options Delimiter (--): The double dash tells the parser that all subsequent arguments are strictly positional operands.

## Level 2 to Level 3: Spaces and Special Characters in Filenames

Objective: Read a file titled "spaces in this filename".

Commands:
cat "spaces in this filename"

Core Concepts Learned:
1. Shell Tokenization & Word Splitting: Bash uses whitespace to separate arguments. Without quotes or backslash escapes, cat attempts to open four separate files instead of one.

## Level 5 to Level 6: Advanced Metadata Querying (find)

Objective: Locate a human-readable, non-executable file that is exactly 1033 bytes in size within the inhere directory tree.

Commands:
cd inhere
find . -type f -size 1033c ! -executable
cat ./maybehere07/.file2

Core Concepts Learned:
1. Exact Byte Size Matching (-size 1033c): The "c" flag forces find to measure in individual bytes rather than default blocks (512 bytes) or kilobytes (k).
2. Logical Inversion in CLI Filters (!): The exclamation mark negates expression checks, allowing exclusion of executable binaries and scripts.
3. Recursive Tree Traversal: find traverses deeply nested subdirectories without requiring explicit scripting or manual path checking.

## Level 6 to Level 7: System-Wide Queries & Stream Redirection

Objective: Locate a file anywhere on the filesystem owned by user bandit7, owned by group bandit6, and exactly 33 bytes in size.

Commands:
find / -user bandit7 -group bandit6 -size 33c 2>/dev/null
cat /var/lib/dpkg/info/bandit7.password

Core Concepts Learned:
1. Root-Level Filesystem Scans (find /): Directs the search utility to traverse the entire filesystem hierarchy starting from the root directory.
2. Standard Error Redirection (2>/dev/null): Standard error runs on file descriptor 2 (stderr). Redirecting it to /dev/null silences "Permission denied" errors generated by unprivileged access across system directories, surfacing only matching stdout paths.
3. POSIX User & Group Filtering (-user, -group): Enables querying assets strictly by UID and GID ownership properties.

## Level 8 to Level 9: Stream Sorting & Unique Frequency Analysis (sort | uniq)

Objective: Retrieve the password stored in data.txt, which is the only line of text that occurs exactly once among hundreds of repeated entries.

Commands:
sort data.txt | uniq -u

Core Concepts Learned:
1. Stream Sorting (sort): The uniq utility operates solely on adjacent duplicate lines. Unsorted streams with identical records separated across lines bypass detection; piping through sort ensures all identical records cluster into contiguous blocks.
2. Unique Filtering (uniq -u): While standard uniq collapses adjacent duplicates, the -u flag filters out any line with a frequency greater than 1, extracting the single non-repeating record.
3. Unix Pipeline Architecture (|): Streams stdout from sort directly into the stdin buffer of uniq in-memory without generating intermediate temporary files.

## Level 9 to Level 10: Extracting Printable Human-Readable Strings (strings)

Objective: Retrieve the password hidden inside the binary data file data.txt, preceded by several '=' characters.

Commands:
strings data.txt | grep "==="

Core Concepts Learned:
1. Binary Stream Parsing (strings): Inspecting raw binary, compiled objects, or corrupted data with cat dumps non-printable control characters that can corrupt terminal emulators. The strings utility filters out unprintable bytes and extracts contiguous sequences of printable ASCII/UTF-8 characters (default minimum length of 4).
2. Pattern Filtering on Binary Artifacts (strings | grep): Combines extraction of printable text with regex filtering to isolate specific key-value pairs or flag delimiters from compiled structures, core dumps, or proprietary binary formats.

## Level 10 to Level 11: Base64 Stream Decoding (base64 -d)

Objective: Retrieve the password stored in data.txt, which contains base64 encoded data.

Commands:
base64 -d data.txt

Core Concepts Learned:
1. Data Representation vs. Encryption: Base64 is an encoding scheme designed to safely transport binary data across 7-bit ASCII transmission channels, not a mechanism for confidentiality. It provides zero cryptographic security.
2. Radix-64 Translation: The algorithm transforms groups of 24 bits (3 bytes) into four 6-bit index values mapped against a 64-character alphabet, padding unaligned input blocks with '=' symbols.
3. Command-Line Stream Decoding: The -d (--decode) switch reverses the representation transform, converting the ASCII stream back into raw plaintext bytes on standard output.

## Level 11 to Level 12: Stream Character Translation & Substitution Ciphers (tr / ROT13)

Objective: Retrieve the password stored in data.txt, where all lowercase and uppercase letters have been rotated by 13 positions (ROT13 Caesar cipher).

Commands:
tr 'A-Za-z' 'N-ZA-Mn-za-m' < data.txt

Core Concepts Learned:
1. Stream Translation Primitives (tr): The translate utility reads standard input, mapping each character from a defined source set (SET1) to the corresponding positional character in a destination set (SET2) before emitting bytes to standard output.
2. ROT13 Reversibility: Because standard Latin alphabet ranges contain 26 letters, shifting indices by 13 positions creates an involutory cipher ($13 + 13 = 26 \equiv 0 \pmod{26}$). Applying the identical transformation a second time decodes the ciphertext without separate decryption logic.
3. Input Stream Redirection (<): Directs file contents from data.txt straight into tr's standard input descriptor (stdin / 0), bypassing unnecessary intermediate utilities like cat.

## Level 12 to Level 13: Binary Hex Reversal & Nested Archive Carving (xxd, file, tar, gzip, bzip2)

Objective: Extract the password hidden within a repeatedly compressed hex dump in data.txt.

Commands:
# In temporary directory /tmp/bandit12_work:
xxd -r data.txt decompressed_data
file decompressed_data

# Iteratively unpack based on signature detection:
mv decompressed_data file.gz && gunzip file.gz
file file
mv file file.bz2 && bunzip2 file.bz2
file file
tar -xf file
# Repeat until final ASCII text key is surfaced
cat <final_extracted_file>

Core Concepts Learned:
1. Reversing Hexadecimal Dumps (xxd -r): The -r (revert) flag parses ASCII hexadecimal representation strings back into their original binary stream format.
2. File Header Magic Signatures (file): File extensions on Unix are arbitrary metadata conventions. Tools like file parse binary magic bytes (e.g., 0x1F8B for Gzip, 0x425A for Bzip2, 0x7573746172 for POSIX tar) to determine true file formats.
3. Multi-Layer Archive Carving: Teaches defensive payload analysis and unpack routines common in malware triage, where nested compression is used to evade basic string scanners.

## Level 13 to Level 14: SSH Private Key Authentication & Key Permissions (ssh -i)

Objective: Retrieve the password for Bandit Level 14 using the private SSH key stored in `sshkey.private` on `localhost`.

Commands:
# Verify restrictive permissions (required by OpenSSH client):
chmod 600 sshkey.private

# Authenticate locally to Level 14 via loopback:
ssh -i sshkey.private bandit14@localhost -p 2220

# Retrieve password from standard system location:
cat /etc/bandit_pass/bandit14

Core Concepts Learned:
1. Public-Key Authentication (`ssh -i`): Replaces password-based authentication with asymmetric key pairs. The `-i` (identity file) flag instructs the OpenSSH client to sign challenge data using the private key matching the public key registered in `~/.ssh/authorized_keys`.
2. OpenSSH Client Key Permission Checks: SSH clients enforce strict filesystem permission boundaries on private keys. If a key file has group or world-readable permissions (e.g., `chmod 644` or `777`), the OpenSSH client rejects it with `WARNING: UNPROTECTED PRIVATE KEY FILE!`. A permission state of `chmod 600` (read/write only by owner) is mandatory.
3. Loopback Connection (`localhost` / `127.0.0.1`): Demonstrates establishing network and port connections entirely within the internal system loopback interface without external internet exposure.

## Level 14 to Level 15: Network Socket Communication & Port Submission (nc)

Objective: Submit the current level's password to a daemon listening on `localhost` port `30000` to receive the password for Bandit Level 15.

Commands:
# Interactive submission via Netcat:
nc localhost 30000

# Alternative single-line pipeline submission:
cat /etc/bandit_pass/bandit14 | nc localhost 30000

Core Concepts Learned:
1. TCP Socket Probing (`nc` / Netcat): Dubbed the "Swiss Army knife of networking," Netcat establishes arbitrary TCP/UDP connections and binds them directly to standard input and standard output streams (`stdin`/`stdout`).
2. Client-Server Interaction Model: Demonstrates programmatic service consumption. The server daemon on port 30000 listens for an incoming connection, evaluates incoming stream data against an expected credential format, and returns the next authentication token upon validation.
3. Pipeline Data Streaming: Combining `cat` with `| nc` eliminates manual keystroke delays, piping file contents directly into the established network transport layer.

## Level 15 to Level 16: Encrypted Socket Communication over TLS (openssl s_client)

Objective: Submit the current level's password to a daemon on `localhost` port `30001` that uses SSL/TLS encryption to receive the password for Bandit Level 16.

Commands:
# Connect directly via OpenSSL's generic TLS client wrapper:
openssl s_client -connect localhost:30001

# Alternative clean stream submission (ignoring SSL handshake noise):
openssl s_client -quiet -connect localhost:30001 < /etc/bandit_pass/bandit15

Core Concepts Learned:
1. Transport Layer Security (TLS/SSL): Cleartext TCP utilities like Netcat fail when interacting with endpoints requiring cryptographic handshakes, cipher-suite negotiation, and certificate exchange.
2. OpenSSL Diagnostic Client (`openssl s_client`): A diagnostic tool for establishing raw encrypted streams to arbitrary TLS-wrapped network services.
3. Suppressing Handshake Overhead (`-quiet`): The `-quiet` switch silences certificate verification details, session parameters, and TLS handshake output, piping standard input and output cleanly across the encrypted tunnel.

## Level 16 to Level 17: Local Port Scanning & Service Fingerprinting (nmap / openssl)

Objective: Identify which service listening on ports `31000-32000` on `localhost` speaks SSL/TLS, submit the credentials for Bandit 16, and use the returned RSA private key to access Bandit Level 17.

Commands:
# 1. Scan the targeted port range on loopback:
nmap -p 31000-32000 localhost

# 2. Probe service versions to isolate the SSL/TLS listener:
nmap -sV -p 31000-32000 localhost

# 3. Connect to the validated TLS daemon and submit credentials:
openssl s_client -quiet -connect localhost:<TARGET_PORT>

# 4. Save returned private key, lock permissions, and authenticate:
mkdir -p /tmp/b16_recon && cd /tmp/b16_recon
cat > bandit17.key << 'EOF'
[RSA Private Key]
EOF
chmod 600 bandit17.key
ssh -i bandit17.key bandit17@localhost -p 2220

Core Concepts Learned:
1. Port Range Scanning (`nmap -p`): Demonstrates targeted reconnaissance across a closed port window on the loopback interface (`127.0.0.1`), locating listening sockets without scanning all 65,535 ports.
2. Service Fingerprinting (`nmap -sV`): Differentiates simple dummy or echo listeners from daemons expecting structured TLS handshakes.
3. Keyfile Lifecycle & Permission Boundaries: Reinforces the OpenSSH requirement for strict identity key permissions (`chmod 600`) before allowing programmatic asymmetric key exchange.

## Level 17 to Level 18: File Modification & Delta Analysis (diff)

Objective: Identify the single modified password line between `passwords.old` and `passwords.new` in the home directory.

Commands:
# Standard line-by-line delta comparison:
diff passwords.old passwords.new

# Alternative side-by-side comparison suppressing identical lines:
diff -y --suppress-common-lines passwords.old passwords.new

Core Concepts Learned:
1. Differential File Analysis (`diff`): Uses Myers' diff algorithm (shortest edit script) to compute the minimal sequence of insertions, deletions, and alterations between two text files.
2. Standard Unix Diff Notation: Output headers like `<` designate records unique to the source file (`passwords.old`), while `>` identifies newly added or altered records in the destination file (`passwords.new`).
3. Configuration Integrity & Audit Triage: File delta inspection is fundamental in incident response and version auditing, isolating unauthorized configuration mutations or injected lines without manual manual review.
