# Bandit Levels 00 to 07 Walkthrough & Core Concepts

---

## Level 0 to Level 1: Remote Access & Encrypted Channels

Objective: Establish an authenticated, encrypted interactive shell session with the remote game server host.

Commands:
ssh bandit0@bandit.labs.overthewire.org -p 2220
ls
cat readme
exit

Core Concepts Learned:
1. Transport Layer Port Addressing (-p 2220): Standard SSH daemons listen on TCP port 22. Labs and servers often remap SSH to alternative ports like 2220 to avoid scanner noise or conflicts. The -p flag forces OpenSSH to target port 2220.
2. Host Authentication & Fingerprint Verification: On initial connection, SSH warns that the authenticity cannot be established and checks the remote public key against ~/.ssh/known_hosts to protect against Man-in-the-Middle (MitM) attacks.
3. Standard File Output (cat): The cat utility reads files sequentially and streams their contents to standard output (stdout).

## Level 1 to Level 2: Dashed Filenames & Argument Parsing

Objective: Read the contents of a file named "-" in the home directory.

Commands:
cat ./-
cat -- -

Core Concepts Learned:
1. POSIX Option Parsing: CLI utilities treat tokens starting with "-" as options/flags rather than file arguments.
2. Special Meaning of Single Dash (-): In tools like cat, a lone "-" represents stdin (standard input), causing the shell to wait for keyboard input rather than opening a file.
3. Path Disambiguation (./-): Adding the relative path prefix "./" prevents the parser from reading "-" as a flag because the argument starts with ".".
4. End-of-Options Delimiter (--): The double dash tells the parser that all subsequent arguments are strictly positional operands.

## Level 2 to Level 3: Spaces and Special Characters in Filenames

Objective: Read a file titled "spaces in this filename".

Commands:
cat "spaces in this filename"
cat spaces\ in\ this\ filename

Core Concepts Learned:
1. Shell Tokenization & Word Splitting: Bash uses whitespace to separate arguments. Without quotes or backslash escapes, cat attempts to open four separate files instead of one.

## Level 3 to Level 4: Hidden Files & Directory Navigation

Objective: Locate and extract the key hidden in the "inhere" directory.

Commands:
cd inhere
ls -la
cat .hidden

Core Concepts Learned:
1. Unix Dotfiles: Files prefixed with "." are treated as hidden by default convention. The -a flag instructs ls to display all directory contents without filtering out dotfiles.

## Level 4 to Level 5: Binary vs. Human-Readable Inspection

Objective: Identify the single human-readable ASCII file among multiple binary files.

Commands:
cd inhere
file ./*
cat ./-file07

Core Concepts Learned:
1. Magic Numbers & MIME Detection (file): Linux file extensions are arbitrary labels. The file utility checks file headers, magic numbers, and byte encodings (ASCII, UTF-8, binary) to safely classify contents before displaying them.

## Level 5 to Level 6: Advanced Metadata Querying (find)

Objective: Locate a human-readable, non-executable file that is exactly 1033 bytes in size within the inhere directory tree.

Commands:
cd inhere
find . -type f -size 1033c ! -executable
cat ./maybehere07/.file2

Core Concepts Learned:
1. Exact Byte Size Matching (-size 1033c): The "c" flag forces find to measure in individual bytes rather than default blocks (512 bytes) or kilobytes (k).
2. Logical Inversion in CLI Filters (!): The exclamation mark negates expression checks, allowing exclusion of executable binaries and scripts.
3. Recursive Tree Traversal: find traverses deeply nested subdirectories without requiring explicit scripting or manual path checking.

## Level 6 to Level 7: System-Wide Queries & Stream Redirection

Objective: Locate a file anywhere on the filesystem owned by user bandit7, owned by group bandit6, and exactly 33 bytes in size.

Commands:
find / -user bandit7 -group bandit6 -size 33c 2>/dev/null
cat /var/lib/dpkg/info/bandit7.password

Core Concepts Learned:
1. Root-Level Filesystem Scans (find /): Directs the search utility to traverse the entire filesystem hierarchy starting from the root directory.
2. Standard Error Redirection (2>/dev/null): Standard error runs on file descriptor 2 (stderr). Redirecting it to /dev/null silences "Permission denied" errors generated by unprivileged access across system directories, surfacing only matching stdout paths.
3. POSIX User & Group Filtering (-user, -group): Enables querying assets strictly by UID and GID ownership properties.

## Level 7 to Level 8: Stream Pattern Matching (grep)

Objective: Retrieve the password stored in data.txt next to the word "millionth".

Commands:
grep "millionth" data.txt

Core Concepts Learned:
1. Text Pattern Matching (grep): Global Regular Expression Print parses large text streams line-by-line to match specific substrings without flooding the terminal buffer.
2. Handling Bulk Data Logs: Avoids opening multi-megabyte log dumps manually with cat or less by isolating targeted records at the command line.

## Level 8 to Level 9: Stream Sorting & Unique Frequency Analysis (sort | uniq)

Objective: Retrieve the password stored in data.txt, which is the only line of text that occurs exactly once among hundreds of repeated entries.

Commands:
sort data.txt | uniq -u

Core Concepts Learned:
1. Stream Sorting (sort): The uniq utility operates solely on adjacent duplicate lines. Unsorted streams with identical records separated across lines bypass detection; piping through sort ensures all identical records cluster into contiguous blocks.
2. Unique Filtering (uniq -u): While standard uniq collapses adjacent duplicates, the -u flag filters out any line with a frequency greater than 1, extracting the single non-repeating record.
3. Unix Pipeline Architecture (|): Streams stdout from sort directly into the stdin buffer of uniq in-memory without generating intermediate temporary files.

---

## Level 9 to Level 10: Extracting Printable Human-Readable Strings (strings)

Objective: Retrieve the password hidden inside the binary data file data.txt, preceded by several '=' characters.

Commands:
strings data.txt | grep "==="

Core Concepts Learned:
1. Binary Stream Parsing (strings): Inspecting raw binary, compiled objects, or corrupted data with cat dumps non-printable control characters that can corrupt terminal emulators. The strings utility filters out unprintable bytes and extracts contiguous sequences of printable ASCII/UTF-8 characters (default minimum length of 4).
2. Pattern Filtering on Binary Artifacts (strings | grep): Combines extraction of printable text with regex filtering to isolate specific key-value pairs or flag delimiters from compiled structures, core dumps, or proprietary binary formats.

---

## Level 10 to Level 11: Base64 Stream Decoding (base64 -d)

Objective: Retrieve the password stored in data.txt, which contains base64 encoded data.

Commands:
base64 -d data.txt

Core Concepts Learned:
1. Data Representation vs. Encryption: Base64 is an encoding scheme designed to safely transport binary data across 7-bit ASCII transmission channels, not a mechanism for confidentiality. It provides zero cryptographic security.
2. Radix-64 Translation: The algorithm transforms groups of 24 bits (3 bytes) into four 6-bit index values mapped against a 64-character alphabet, padding unaligned input blocks with '=' symbols.
3. Command-Line Stream Decoding: The -d (--decode) switch reverses the representation transform, converting the ASCII stream back into raw plaintext bytes on standard output.
